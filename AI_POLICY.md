# AI Policy

We support using AI (i.e., LLMs) as tools when contributing to Project Red projects. However, you are responsible for any contributions you submit, and we are responsible for any contributions we merge and release. We hold a high bar for all contributions to our projects.

Our maintainers dedicate their time and expertise to reviewing contributions. Submitting AI-generated content that you have not personally reviewed and understood wastes that time and will not be accepted.

## Autonomous agents

**We allow autonomous agents to be used for contributing to our projects.** We allow team members to use agents to create issues or raise Merge Requests using an agent but these must be done with human oversight, no pointing an agent at the codebase and saying "find bugs and raise issues". Each issue must be reviewed by the submitter and as with any code generated by AI it is your responsibility to make sure the Issue/MR is correct, well formed, follows our templates, and most importantly, can be followed by a human.

If a potential bug is discovered by an LLM but you have no verified it yourself you _may_ raise an issue (following all the rules!) but ensure it is labelled with the `Bug::LLM Discovered`, the equivialent to the human `Bug::Unconfirmed`.

## Communication on issues, pull requests, and code reviews

We don't mind if you use AI tools to help you write. However, do not have tools post unreviewed content on your behalf. Keep responses to the minimum needed to communicate your intent. We may hide any comments that we believe are unreviewed AI output.

If you are opening a merge request, we expect you to be able to explain the proposed changes in your own words. This includes the merge request description and responses to questions. If you use AI to help generate the pull request summary, you must review it for technical accuracy.

**Do not use AI to generate answers to questions from maintainers.** You should understand and be able to explain your own work. Using AI to improve grammar or clarity is fine, but the substance of your responses must be your own.

If you wish to include context from an interaction with AI in your comments, it must be clearly marked as "AI/LLM Output" wether that's with a heading or short preamble. It must be accompanied by your own commentary explaining the relevance and implications of the context.

## Non-native English speakers

We understand that AI is useful when communicating as a non-native English speaker. Using AI to improve the grammar or clarity of text you have written yourself is fine. If you are using AI to translate your comments, please ensure the translation accurately reflects your intent. Including your original text in a details block shows the effort behind your contribution, helps maintainers verify the translation if needed, and keeps the conversation readable.

## Code and documentation contributions

AI can be a helpful tool for writing code and documentation. However, due to the foundational open source nature of our projects, we require a human in the loop who understands the work produced by AI.

All contributions must be reviewed and understood by the contributor before submission. You should be able to explain every change in a pull request you submit. Pull requests that appear to be unreviewed AI output will be closed without review.

## Our use of AI

Some of our members use AI tools to assist with code reviews, issue triaging, reporting, and other project management tasks. These tools may leave comments on pull requests or issues. As with any automated tooling, these comments are not always correct.

If an AI tool leaves a comment on your contribution, treat it as you would any other review comment. If you believe it is incorrect, say so; a brief explanation is sufficient. Maintainers always have the final say. If in doubt, ask a maintainer.

### Foundry VTT AI Policy Compliance

As our project is tightly coupled to Foundry VTT we must also comply with their [AI policy](https://foundryvtt.com/article/ai-policy/) in both the `core` and `dlc` repos. This boils down to mostly the above for code (you own it, you must understand it), and we **cannot** use it for image generation.

## Enforcement

Contributions that do not follow this policy will be closed. Repeated violations may result in being blocked from contributing to our projects. If you believe your contribution was closed in error, you are welcome to reach out to a maintainer to discuss.
